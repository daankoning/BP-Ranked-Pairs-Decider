About

In cases where, due to splits, the panel is unable to resolve to a single ranking of teams, the manual requires chairs to use the ranked pairs algorithm to decide the debate.1 In practice, it appears knowledge of this system is limited. Even for chairs aware of the algorithm, applying it by hand during a time-constrained deliberation is slow and error-prone: a single misordered comparison can change the result. This tool handles the bookkeeping, leaving the chair only the decisions the manual reserves for them.

Ranked Pairs

The ranked pairs algorithm for BP is outlined in section 3.2 of the Judging Manual and is a special case of the more general Tideman method.2 After calling a vote on each pairwise comparison, each of the six comparisons is sorted by the margin (the number of judges in the majority minus those in the minority). In the likely event that this ranking has ties, the chair resolves them by ranking the tied comparisons using their judgement.

The resulting list of comparisons is then iterated on. The highest-sorted comparison is fixed and the method proceeds to the next-highest comparison: if it contradicts any previously fixed comparisons, it is discarded, otherwise, it is also fixed. This repeats until a complete ranking is obtained.

Using This Tool

Enter the panel’s votes on each of the six pairwise comparisons. Where the panel is split evenly on a comparison, the tool asks for the chair’s casting vote. If the comparisons do not all add up to the same number of judges, a warning is shown, as this usually indicates a typo.

Once all six comparisons are in, they are sorted by margin. Ties in margin are common, but their order only matters if it changes which comparisons are discarded. The tool works out which ties affect the outcome and asks the chair to break only those; the rest are left tied and marked with =. Redo tiebreaks undoes these choices.

The result gives the final ranking of teams, along with any votes that were discarded. The full sequence of fixed and discarded comparisons is shown under How this was reached, which may be useful when explaining the call to the panel.
